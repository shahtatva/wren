# Perch UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle Wren's web app as Perch, where a drawn wren on a branch is the talk button and its posture shows the voice state. Add the "What Wren knows" page, plus the voice-server routes that read and change what Wren remembers.

**Architecture:**
- **Voice server:** six `/knows` routes in a new `knows_routes.py`. They call new store functions that run inside `store.as_user`, so RLS scopes every row.
- **Web, look:** new color tokens and the Recursive font. A pure `birdView()` maps the voice state to a pose, and a `Bird`/`Perch` SVG component is posed by CSS. The talk screen is rebuilt around the bird.
- **Web, `/knows`:** the page's data, view and form logic live in plain `lib/` modules that `node --test` checks.

**Tech Stack:** Next.js 16.4 App Router, React 19.3, Tailwind v4, `next/font/google` (Recursive with its CASL axis) and `node --test`. FastAPI, pydantic, psycopg 3 and pytest. Playwright (Python) for browser checks.

**Spec:** [docs/superpowers/specs/2026-11-11-perch-ui-design.md](../specs/2026-11-11-perch-ui-design.md). The visual source is row A of the [design canvas](https://claude.ai/artifact/1GQHZqjFSmX9z2dNvciGwP). Every value the build needs from it is copied into this plan.

## Global Constraints

- **Browser and secrets:** the browser talks only to `voice/` through `VOICE_SERVER_URL`. No keys and no Supabase calls in `web/`.
- **RLS:** stays on. Every `/knows` query runs inside `store.as_user(conn, user_id)`, and every new store function also filters by `user_id`.
- **Dependencies:** no new dependencies on either side. Free tiers only.
- **Logs:** never log memory text, interview fields or profile fields. Log route names and exception type names only.
- **Live path:** unchanged. `/turn`, `/ws`, retrieval and the voice client's timing stay as they are. Wren's level stays one `style.setProperty("--level", …)` per callback, with no re-render.
- **Copy:** use the copy exactly as written here and in the spec (wren-voice skill). Trust screens are plain, Wren speaks in first person only in its own messages, and there are no exclamation marks.
- **Next.js 16:** it differs from older versions. Read the relevant file in `web/node_modules/next/dist/docs/` before using a Next API (`web/AGENTS.md`).
- **Mobile-first:**
  - Every screen works at 390 × 844 and 375 × 667 with no sideways scroll.
  - Tap targets are at least 44 px, and keyboard focus is always visible.
  - `prefers-reduced-motion: reduce` stops every animation loop.
- **Commits:** one per task, on branch `perch-ui`, in the repo's plain-sentence style. Each ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Database tests:** pipe their output through `sed -E 's/password=[^ ]+/password=***/g'`.

```python
@dataclass(frozen=True)
class Source:
    """Where a remembered item came from: its session's mode and start. When that session is gone,
    mode is None and at is when the item was saved."""
    mode: str | None
    at: datetime

@dataclass(frozen=True)
class KnownMemory:
    id: str
    kind: str
    text: str
    source: Source

@dataclass(frozen=True)
class InterviewFields:
    company: str
    role: str | None
    stage: str
    next_date: date | None
    next_time: time | None
    notes: str | None

@dataclass(frozen=True)
class KnownInterview:
    id: str
    fields: InterviewFields
    source: Source
    moved_from: tuple[tuple[date | None, time | None], ...]  # older versions' date and time, newest first

@dataclass(frozen=True)
class Knows:
    timezone: str  # the profile's, or "UTC" with no profile
    profile: Profile | None
    pipeline: tuple[KnownInterview, ...]
    memories: tuple[KnownMemory, ...]  # current only, newest first
```

- Produces, in `store.py`. Every function also takes the keyword argument `schema: str = "public"`.
  - `load_knows(conn, user_id: UUID) -> Knows`
  - `update_memory_text(conn, user_id: UUID, memory_id: UUID, text: str, embedding: list[float]) -> KnownMemory | None`
  - `delete_memory(conn, user_id: UUID, memory_id: UUID) -> bool`
  - `update_interview(conn, user_id: UUID, interview_id: UUID, fields: InterviewFields) -> KnownInterview | None`
  - `delete_interview(conn, user_id: UUID, interview_id: UUID) -> bool`
  - `update_profile(conn, user_id: UUID, changes: Mapping[str, object]) -> Profile`. `changes` can hold `display_name` (str | None), `summary` (str) and `target_roles` (list[str]). Other keys are ignored.
  - **Return values:** `None` or `False` means this user has no such current row. Only current rows (`superseded_by is null`) can be edited or deleted.

- [ ] **Step 3: Add the types and the store functions**

Add the types listed under Interfaces. In `store.py`:

- **Scope:** every function filters by `user_id = %s` as well as relying on RLS, and starts only from current rows.
- **A row's source:** `left join {sessions} s on s.id = x.source_session`, read as `Source(s.mode, coalesce(s.started_at, x.created_at))`.
- **`load_knows`:**
  - It calls `load_profile`, then reads the memories ordered `coalesce(s.started_at, m.created_at) desc, m.created_at desc, m.id`, then the interviews ordered `next_date, next_time, company, id`. The page sorts interviews again against today.
  - A private `_interviews(conn, user_id, schema, only: UUID | None = None)` reads the current rows and their history. `update_interview` reuses it with `only` after its update.
  - History is one recursive query, numbered by depth:

```sql
with recursive chain as (
  select id as head, id, next_date, next_time, 0 as depth
  from {pipeline} where user_id = %(user_id)s and superseded_by is null
  union all
  select c.head, p.id, p.next_date, p.next_time, c.depth + 1
  from {pipeline} p join chain c on p.superseded_by = c.id
)
select head, next_date, next_time from chain where depth > 0 order by head, depth, id
```

- **Deletes:** each delete is one statement, so an older version can never become current again (`superseded_by` is `on delete set null`). The function returns `cursor.rowcount > 0`.

```sql
with recursive chain as (
  select id from {table} where id = %s and user_id = %s and superseded_by is null
  union all
  select t.id from {table} t join chain c on t.superseded_by = c.id
)
delete from {table} where id in (select id from chain)
```

- **`update_memory_text`:** sets `text` and `embedding` (`to_pgvector(...)`, cast to `extensions.vector`) and nothing else. `tsv` is a generated column, so it follows the new text.
- **`update_profile`:**
  - Upserts only the columns it's given: `insert … on conflict (user_id) do update set <col> = excluded.<col>`.
  - Column names come only from the fixed list `("display_name", "summary", "target_roles")`, through `sql.Identifier`.
  - Returns `load_profile(...)`. A new row gets the table's defaults, including time zone `UTC`.

- **Produces, in `live.py`:**
  - `class MemoryOff(Exception)`.
  - These methods on the `Memory` protocol. `NoMemory` implements each by raising `MemoryOff(self.status)`, and `PostgresMemory` implements them for real.
    - `async knows(user_id) -> Knows`
    - `async edit_memory(user_id, memory_id: UUID, text: str) -> KnownMemory | None`. It embeds `text` with `embed_texts([text], "document", settings)` first, so a failed embedding raises and changes nothing.
    - `async delete_memory(user_id, memory_id: UUID) -> bool`
    - `async edit_interview(user_id, interview_id: UUID, fields: InterviewFields) -> KnownInterview | None`
    - `async delete_interview(user_id, interview_id: UUID) -> bool`
    - `async edit_profile(user_id, changes: dict[str, object]) -> Profile`
- **Produces, over HTTP** (Task 6 reads these shapes):

| Route | Body | Success |
| --- | --- | --- |
| `GET /knows` | none | 200 `{timezone, profile, pipeline: [interview], memories: [memory]}` |
| `PATCH /knows/memories/{id}` | `{text}` | 200 memory |
| `DELETE /knows/memories/{id}` | none | 204 |
| `PATCH /knows/pipeline/{id}` | `{company, role, stage, next_date, next_time, notes}` | 200 interview |
| `DELETE /knows/pipeline/{id}` | none | 204 |
| `PATCH /knows/profile` | any of `{display_name, summary, target_roles}` | 200 profile |

  - **memory:** `{id, kind, text, source}`.
  - **interview:** `{id, company, role, stage, next_date: "YYYY-MM-DD" | null, next_time: "HH:MM" | null, notes, source, moved_from: [{next_date, next_time}]}`.
  - **profile:** `{display_name, summary, target_roles}`, or `null` when there's no profile.
  - **source:** `{mode: "checkin" | "mock" | null, at: ISO 8601 with offset}`.
  - **Refusals** are `{code, message}`:

| Status | Code | Message |
| --- | --- | --- |
| 401 | `unauthorized` | from `admit()` |
| 403 | `age_unconfirmed` | from `admit()` |
| 404 | `not_found` | "That isn't there anymore." |
| 503 | `memory_off` | "Wren's memory is off right now. Try again later." |
| 503 | `unavailable` (the GET) | "I can't reach Wren's memory right now. Try again in a minute." |
| 503 | `not_saved` (writes) | `NOT_SAVED` from `auth_routes` |
| 503 | `age_check_failed` | from `admit()` |

  - Bad input gets FastAPI's 422, and a disallowed origin gets 403 before anything else.
- **Limits, after trimming:**

| Field | Limit |
| --- | --- |
| Memory text | 1 to 1,000 characters |
| Company | 1 to 200 |
| Role | up to 200 |
| Stage | 1 to 100 |
| Notes | up to 1,000 |
| Display name | up to 100 |
| Summary | up to 1,000 |
| Target roles | up to 10 roles, each 1 to 100 |

  - A blank role, note or display name becomes `null`.
  - A profile PATCH must name at least one field.

function tokens(block: string): Record<string, string> {
  return Object.fromEntries([...block.matchAll(/--([a-z-]+):\s*(#[0-9a-f]{6})\b/gi)].map((m) => [m[1], m[2].toLowerCase()]));
}

function luminance(hex: string): number {
  const [r, g, b] = [1, 3, 5].map((i) => {
    const c = parseInt(hex.slice(i, i + 2), 16) / 255;
    return c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4;
  });
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
}

function contrast(a: string, b: string): number {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x);
  return (hi + 0.05) / (lo + 0.05);
}

type Call = { method: string; url: string; body: unknown; authorization: string | null };

// The voice server's /knows routes: every request answers from `answer`.
function server(answer: (call: Call) => { status: number; body?: unknown }) {
  const calls: Call[] = [];
  const fetch = async (url: string | URL | Request, init: RequestInit = {}) => {
    const call = {
      method: init.method ?? "GET", url: String(url),
      body: init.body ? JSON.parse(String(init.body)) : undefined,
      authorization: new Headers(init.headers).get("authorization"),
    };
    calls.push(call);
    const { status, body } = answer(call);
    return new Response(body === undefined ? null : JSON.stringify(body), { status });
  };
  return { calls, fetch: fetch as typeof globalThis.fetch };
}

  new KnowsApi({ base: BASE, fetch: s.fetch, token });

  const s = server(() => ({ status: 200, body: KNOWS }));
  assert.deepEqual(await api(s).load(), { ok: true, value: KNOWS });
  assert.deepEqual(s.calls, [{ method: "GET", url: `${BASE}/knows`, body: undefined, authorization: "Bearer tok" }]);
});

  const s = server(() => ({ status: 200, body: KNOWS }));
