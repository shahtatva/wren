# Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wren works on the owner's phone: the voice server runs on Render, and the web app on Vercel talks to it, with sign-in.

**Architecture:**
- **Three hardening changes come first,** each test-first:
  - a deadline on every send to Deepgram, so one stalled send can't freeze a live session;
  - the API docs pages are off, and the image clears the dev identity in a way `.env` can't undo;
  - security headers on the web app, with a content security policy that limits where the page can connect.
- **Then the deploy:**
  - push master to GitHub;
  - the owner creates the Render service;
  - Vercel gets the voice server's URL, and a build that passed the key-leak check goes to production;
  - the owner checks it on the phone.

**Tech Stack:** FastAPI, Docker (`voice/Dockerfile`), Render's free web service, Next.js 16 on Vercel (`npx vercel@64.5.0`), pytest, `node --test`. No new dependencies or accounts beyond Render, which the owner chose in session 4.

**Spec:**
- `docs/superpowers/specs/2026-10-16-voice-loop-design.md`: "Keys and access" and "Fallbacks and limits".
- The walkthrough in `logs/logs_session-4.md` (git-ignored), section 5: host, region and settings.
- The sign-in review's deploy notes (`logs/session-6/sign-in-ledger.md`, "Final" lines).
- `CLAUDE.md`

**Not in this plan:**
- per-client-IP limits on `voice/`, which need the host's proxy headers trusted first, and `Sb-Forwarded-For` (both listed in the design doc's "What throttling can't fix");
- the query-rewrite decision and Wren's reply length;
- the owner's mic-while-speaking idea, which waits until Wren works on the phone.

## Global Constraints

- Free tiers only. Render: free web service, region Virginia (next to the Supabase pooler). Vercel: the existing `tatva-dev/wren` project.
- No key reaches the browser. `python -m app.tools.leak_check` passes on the build that's deployed, run with the dev server stopped.
- `WREN_DEV_USER_ID` is never set on the deployed server.
- One uvicorn process, no workers: live sessions sit in its memory.
- `ALLOWED_ORIGINS` names exactly the production web origins: `https://wren-kappa.vercel.app,https://wren-tatva-dev.vercel.app`.
- Row-level security stays on; sign-in stays invite-only (sign-ups off in the dashboard).
- Outward steps (the push, the Render service, the Vercel production deploy) are the owner's go-ahead, given 2026-10-25 ("Let's get cooking!").

## Review Focus

1. **A cold start.** Render's free instance sleeps after 15 idle minutes and takes about a minute to wake. The first sign-in or hello waits that long. The page must keep retrying, not give up (Task 4 Step 6 checks it live).
2. **The policy blocking the app.** If the CSP leaves out the voice server's `https` or `wss` origin, or the worklets under `/voice/`, sign-in or the mic fails in production only (Task 3's tests and Task 4 Step 5's console check).
3. **An origin mismatch.** A web origin missing from `ALLOWED_ORIGINS` gets its handshake refused with 403. The page then says it can't reach the voice server (Task 4 Step 5).
4. **A stalled Deepgram send mid-reply.** Wren keeps speaking, typed text still works, and hearing comes back by itself (Task 1's tests).
5. **Sign-in on the installed phone app.** An iPhone home-screen app has its own storage, so it needs its own sign-in. The mic starts from a tap (Task 4 Step 6).

### Task 1: A deadline on sends to Deepgram

**Files:**
- Modify: `voice/app/voice/tuning.py` (`stt_send_timeout_s: float = 2.0`)
- Modify: `voice/app/voice/session.py` (the `stt.send` in `_on_audio`, `stt.keep_alive` in `_tick`, and every `stt.finalize`)
- Modify: `voice/tests/voice_fakes.py` (`FakeStt(hang=...)`)
- Test: `voice/tests/test_session.py`

**Interfaces:**
- Produces:
  - `FakeStt(fail=None, hang: set[str] = frozenset())`: methods named in `hang` (`"send"`, `"keep_alive"`, `"finalize"`) wait forever.
  - **In the session:** a send that takes longer than `stt_send_timeout_s` drops speech-to-text as a broken connection. It closes it in the background, sends `{"type": "voice", "available": false, "reason": "stt_stalled"}`, and schedules the usual retry (`_schedule_stt_retry`). Everything else carries on.

- [ ] **Step 1: Write the failing tests:**
  - `test_a_stalled_deepgram_send_drops_hearing_and_keeps_the_session_going`: `FakeStt(hang={"send"})` with a tuning of `stt_send_timeout_s=0.2`. Send one audio frame. Expect `voice` with `available: false` and `reason: "stt_stalled"` within 2 s. Then a `user_text` still gets an answered turn (`reply_end` with outcome `complete`).
  - `test_a_stalled_keepalive_doesnt_freeze_the_ticker`: `FakeStt(hang={"keep_alive"})`, mic off, `keepalive_s=0.1`. Expect `stt_stalled` within 2 s, then a `user_text` is answered.
- [ ] **Step 2: Run them and see them fail.** `cd voice && pytest tests/test_session.py -k stalled -v`. Expected: they time out waiting for `stt_stalled`.
- [ ] **Step 3: Implement** one session helper that wraps each send in `asyncio.wait_for`. On a timeout it logs a warning (never audio or text), closes and drops speech-to-text, and schedules the retry.
- [ ] **Step 4: Run the voice suite.** `cd voice && pytest -q`. Expected: all pass.
- [ ] **Step 5: Commit:** "Give every send to Deepgram a deadline"

### Task 2: Harden the deployed server

**Files:**
- Modify: `voice/app/main.py` (`FastAPI(..., docs_url=None, redoc_url=None, openapi_url=None)`)
- Modify: `voice/Dockerfile` (the start command: `export WREN_DEV_USER_ID=` instead of `unset WREN_DEV_USER_ID`)
- Test: `voice/tests/test_health.py`, `voice/tests/test_voice_config.py`

**Why the Dockerfile change:** `load_dotenv(override=False)` fills a variable that's unset, so an image that ever held a `.env` would bring the dev identity back. An empty variable is never overwritten, and an empty one means no dev identity.

- [ ] **Step 1: Write the failing tests:**
  - `test_the_api_docs_are_not_served`: `GET /docs`, `/redoc` and `/openapi.json` each return 404. `/health` still returns 200.
  - `test_an_empty_dev_user_id_beats_the_env_file`: point `config.ENV_FILE` at a temporary `.env` holding `WREN_DEV_USER_ID=<a uuid>`, and set the variable to empty in the environment. Expect `load_voice_settings().dev_user_id is None`. This is the behavior the start command relies on. It should pass before the change, because it pins existing behavior. The docs test is the one that fails first.
- [ ] **Step 2: Run them.** `cd voice && pytest tests/test_health.py tests/test_voice_config.py -v`. Expected: the docs test fails, and the env test passes.
- [ ] **Step 3: Implement** both changes. Update the Dockerfile's comment to say why the variable is empty rather than unset.
- [ ] **Step 4: Check the image.**
  - From `voice/`: `docker build -t wren-voice .`
  - Then `docker run --rm -d --name wren-check --env-file .env -v "$PWD/.env:/app/.env:ro" -p 8001:8000 wren-voice`. The real `.env` sets `WREN_DEV_USER_ID`, and it's also mounted where `load_dotenv` looks.
  - Then send a hello from inside the container, which counts as loopback: `docker exec wren-check python -c "<websockets hello to ws://127.0.0.1:8000/ws, origin http://localhost:3000, print the reply and the close code>"`.
  - Expected: `unauthorized`, then 4401. Under the old `unset`, this same run lets the dev identity in.
  - Also `/health` on port 8001 returns 200 and `/docs` returns 404. Then `docker stop wren-check`.
- [ ] **Step 5: Run the voice suite and commit:** "Hide the API docs and keep the dev identity off in the image"

### Task 3: Security headers on the web app

**Files:**
- Modify: `web/next.config.ts` (export `securityHeaders(voiceServerUrl: string, dev: boolean): { key: string; value: string }[]`, and an `async headers()` applying it to `/(.*)`)
- Test: `web/tests/security-headers.test.ts`

**Interfaces:**
- Produces: `securityHeaders` returns these headers:
  - `Content-Security-Policy`:
    - `default-src 'self'`
    - `script-src 'self' 'unsafe-inline'`, plus `'unsafe-eval'` in dev only. Next needs inline scripts without nonces, and Cache Components rule nonces out. The worklets load from `/voice/*.mjs`, so `'self'` covers them.
    - `style-src 'self' 'unsafe-inline'`
    - `img-src 'self' blob: data:`
    - `font-src 'self'`
    - `connect-src 'self'` plus the voice server's origin and its socket origin (`http`→`ws`, `https`→`wss`), plus `ws://localhost:3000` in dev for hot reload
    - `object-src 'none'`
    - `base-uri 'self'`
    - `form-action 'self'`
    - `frame-ancestors 'none'`
    - `upgrade-insecure-requests`, in production only, because it would break `http://localhost`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `X-Content-Type-Options: nosniff`
  - `Permissions-Policy: microphone=(self), camera=(), geolocation=()`

- [ ] **Step 1: Write the failing tests:**
  - **production lets the page reach only itself and the voice server:** with `https://wren-voice.onrender.com`, `connect-src` is exactly `'self' https://wren-voice.onrender.com wss://wren-voice.onrender.com`. The policy has `upgrade-insecure-requests` and no `'unsafe-eval'`.
  - **development allows the local servers and hot reload:** with `http://localhost:8000`, `connect-src` includes `http://localhost:8000`, `ws://localhost:8000` and `ws://localhost:3000`. The policy has `'unsafe-eval'` and no `upgrade-insecure-requests`.
  - **the page can't be framed, and the mic is for this site only:** `frame-ancestors 'none'`, and `Permissions-Policy` starts with `microphone=(self)`.
- [ ] **Step 2: Run them and see them fail.** `cd web && npm test`. Expected: `securityHeaders` isn't exported.
- [ ] **Step 3: Implement.** Read `NEXT_PUBLIC_VOICE_SERVER_URL` once, with the same default as `lib/voice-server.ts`. Keep the existing config fields.
- [ ] **Step 4: Check it in the browser.** Run `npm test`, `npm run lint` and `npm run build`. Then run the dev-path browser sessions, with the throwaway dev id: `python web/e2e/session_e2e.py --mode both`. They load the app under the dev policy, so a blocked socket or worklet fails them. Expected: no new failures, and no "Refused to" messages in the console.
- [ ] **Step 5: Commit:** "Add security headers and a content security policy to the web app"
